# D2ロボコン2026 得点板

2025年版RoLIMOAのReact・TypeScript・MUI、効果音とデジタル時計の表示を引き継ぎ、2026年ルールブック **Ver.3（2026-11-12）** に合わせた4人用システムです。

4人の得点入力、主審の採点、会場スクリーン、配信画面を1台のPCで動かし、同じネットワークのスマートフォンや別のPCから操作できます。初回起動は空の状態で、名簿や試合を画面から登録できます。

このリポジトリだけでセットアップできます。2025年版、別のルールブックフォルダー、個人のPC設定は不要です。

## はじめに用意するもの

| 用途 | 必要なもの |
|---|---|
| 得点板を動かすPC（サーバPC） | Node.jsとnpm、書き込み可能な作業フォルダー |
| Node.js | **24 LTSを推奨**。動作確認は24.22.1。プログラムの最低要件は20以降 |
| 操作・表示する端末 | Chrome / Edge / Safariなどのブラウザ。スマホ側にNode.jsは不要 |
| ソフトの取得・初回セットアップ | インターネット接続。Gitはcloneする場合のみ必要 |
| 複数端末で大会を運営する場合 | サーバPCと各端末が互いに通信できるLAN / Wi-Fi |

主にWindows向けの手順です。macOS / Linuxでは後述のnpmコマンドを使用できますが、このプロジェクトでは動作未確認です。

## Windowsでの初回セットアップ

### 1. Node.jsをインストール

[Node.js公式ダウンロード](https://nodejs.org/en/download)から **24 LTS** のWindows用インストーラーを取得し、npmも一緒にインストールします。インストール後は、開いているターミナルを閉じてから開き直してください。

PowerShellまたはコマンドプロンプトで次を実行し、どちらもバージョンが表示されることを確認します。

```powershell
node --version
npm.cmd --version
```

Windowsの手順では `npm.cmd` と表記しています。PowerShellの実行ポリシーで `npm.ps1` が止められる場合も、この表記なら実行ポリシーを変更せずにnpmを使えます。

### 2. ソフトを取得

次のどちらかを選びます。保存場所は任意です。

**ZIPで取得する場合（Git不要）**

1. [GitHubリポジトリ](https://github.com/Robomech-UEC/d2_2026)の「Code」→「Download ZIP」を選びます。
2. ZIPを右クリックし、「すべて展開」で書き込み可能なフォルダーに展開します。
3. 展開先の `README.md`、`package.json`、`setup.cmd` があるフォルダーを開きます。**ZIPの中から直接起動しないでください。**

**Gitで取得する場合**

[Git公式サイト](https://git-scm.com/downloads)からGitをインストールしておきます。ターミナルで保存したい場所を開き、次を実行します。

```powershell
git clone https://github.com/Robomech-UEC/d2_2026.git
cd d2_2026
```

Gitで取得したフォルダー名は `d2_2026`、ZIPを展開したフォルダー名は通常 `d2_2026-main` です。どちらも、以降は **このREADMEがあるフォルダー** で作業します。

### 3. 依存ソフトのインストールとビルド

**`setup.cmd` をダブルクリック**します。依存ソフトをダウンロードした後、実行用ファイルを生成します。`Setup complete` が出たら完了です。セットアップはサーバを自動起動しません。

コマンドで行う場合は、このREADMEがあるフォルダーをターミナルで開いて実行します。

```powershell
npm.cmd ci
npm.cmd run build
```

`node_modules`、`dist`、`client/dist` はセットアップで生成されるためGitHubには含まれません。別のPCに取得したときも、この手順が必要です。

### 4. 起動・終了

**`start.cmd` をダブルクリック**し、ブラウザで [http://localhost:8000](http://localhost:8000) を開きます。コマンドで起動する場合は次のとおりです。

```powershell
npm.cmd start
```

起動中はそのターミナルを開いたままにします。終了するときは、そのウィンドウで **Ctrl+C** を押してください。同じPCでサーバを複数起動する必要はありません。会場画面や入力画面を増やす場合は、ブラウザのタブや別端末からアクセスします。

**2回目以降は `start.cmd` または `npm.cmd start` だけで起動できます。** 初回セットアップと更新時以外に、インターネット接続は不要です。

## スマートフォン・別のPCから接続する

### インターネットのない会場で使う場合

Wi-FiルーターのLANを使えば、インターネット契約やWAN接続なしでも運用できます。ルーターのDHCP機能は有効にしてください。

```text
Wi-Fiルーター（インターネット接続不要）
  ├─ LANケーブルまたはWi-Fi ─ サーバPC（得点板を起動）
  ├─ Wi-Fi ─ スマホ1（紫の入力）
  ├─ Wi-Fi ─ スマホ2（赤の入力）
  ├─ Wi-Fi ─ スマホ3（黄の入力）
  └─ Wi-Fi ─ スマホ4（緑の入力）
```

1. サーバPCと入力端末を同じルーターに接続します。PCを有線接続する場合は **LAN側** のポートにつなぎます。
2. PCで得点板を起動します。Windowsのファイアウォールで通信許可を求められた場合は、会場の信頼できるプライベートネットワークで許可します。必要ならWindowsの設定で、この会場ネットワークを「プライベート」に設定します。
3. PCのターミナルで `ipconfig` を実行し、実際に接続中のWi-Fiまたはイーサネットの **IPv4アドレス** を確認します。Tailscaleなど別のアダプターのアドレスとは区別してください。
4. スマホのブラウザで `http://PCのIPv4アドレス:8000` を開きます。たとえばPCが `192.168.1.10` なら、紫の入力画面は `http://192.168.1.10:8000/score/court1` です。

スマホで `localhost` を開くとスマホ自身に接続するため、サーバPCにはつながりません。URLは **`http://`** で始めてください。PCのIPアドレスはネットワークへの再接続などで変わることがあります。

Wi-Fiが「インターネット未接続」と表示されても、接続を維持してください。ゲストWi-Fiや「AP隔離」「端末間通信禁止」が有効なネットワークでは接続できないことがあります。学校・施設のWi-Fiで制限される場合は、運営用ルーターを利用してください。

<details>
<summary>Windowsファイアウォールで個別にポートを許可する場合</summary>

サーバPCでPowerShellを「管理者として実行」し、次のコマンドを実行します。プライベートネットワークからのTCP 8000番への接続を許可します。ポートを変更した場合は `8000` をその番号に置き換えてください。ファイアウォール全体を無効にする必要はありません。

```powershell
New-NetFirewallRule -DisplayName 'D2 ROBOCON 2026' -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
```

</details>

スマホをモバイル回線など別のネットワークから接続する場合は、別途VPNなどの接続手段が必要です。Tailscaleはインターネットのない会場LANの代わりにはなりません。この得点板には認証がないため、利用は信頼できる端末のネットワーク内に限定し、ルーターのポート開放でインターネットに公開しないでください。

## ポート・保存先を変更する場合

通常は変更不要です。既定のポートは **8000**、保存先は **このREADMEがあるフォルダーの `save`** です。環境変数は起動するターミナルで指定します。次の設定は、そのターミナルで起動する間だけ有効です。

```powershell
$env:PORT = '8001'
$env:D2_SAVE_DIR = Join-Path $env:USERPROFILE 'Documents\D2-2026-records'
npm.cmd start
```

この例では、アクセス先も `http://localhost:8001` に変更します。`D2_SAVE_DIR` は絶対パスを指定してください。保存先を変更すると別の記録として起動するため、既存の記録を使う場合は停止中に `save` の内容を新しい保存先へコピーします。

既定値へ戻すには、同じPowerShellで次を実行してから起動します。

```powershell
Remove-Item Env:PORT -ErrorAction SilentlyContinue
Remove-Item Env:D2_SAVE_DIR -ErrorAction SilentlyContinue
npm.cmd start
```

## 大会での操作

1. **試合管理** `/admin` でCSVを読み込むか、フォームから「予定に追加」で試合を事前登録します。当日は「次の試合を準備」を押すと、試合名・4人の名前・ロボット名が自動で設定されます。1試合だけ手入力する場合は従来の「4人を登録・得点を初期化」も使えます。
2. **会場スクリーン** `/screen` を開きます。効果音を出す1つの画面で「音声を有効にする」を押します。他の画面では音声を有効にしないでください。
3. **試合管理**で「3・2・1で競技開始」を押します。3秒のカウントダウン後に5分間の競技を開始し、時間切れで採点確認へ自動的に移ります。管理画面を閉じても進行します。
4. 担当者は `/score/court1` ～ `/score/court4` で入力します。識別は **1紫・2赤・3黄・4緑** です。「うちゅう到達」で20点と到達順を記録します。同じボタンを再度送信しても重複加点しません。
5. **主審入力** `/referee` で内訳・最終状態・到達順を確認します。到達順はサーバの受付順なので、通信遅延や押し遅れがあれば実際の順に訂正してください。押し間違いの取り消し、到達の補記、個数訂正、失格の指定もできます。
6. 得点・到達順から自動判定し、理由の入力なしで確定できます。**同点かつうちゅうエリアに未到達の参加者は同順位**にします（例：1位タイ・1位タイ・3位・4位）。必要な場合だけ「同点時の主審判定を入力する」をONにし、同順位の並びを変更して理由を記録します。
7. 主審が「試合結果を確定」を押すと入力がロックされ、履歴に保存します。訂正は「確定解除して訂正」から行い、再確定すると同じ試合の履歴を更新します。得点・到達順・失格の変更は、既存の同点判定を解除します。
8. 確定後、試合管理の「次の試合を準備」で未開始の予定を順に呼び出せます。競技中でも先の予定は登録・編集できますが、試合の切り替えは確定後に行います。

得点と順位は競技中は暫定です。カード位置はコート順で固定し、順位が変わっても移動しません。緊急時の一時停止は試合管理から行えますが、**通常のリトライでタイマーを止めたり減点したりしません**。

## 試合の事前登録とCSV

試合管理の「CSVひな形をダウンロード」から取得できる `client/public/matches-template.csv` をExcelなどで編集します。**1行が1試合**です。

```csv
試合名,紫_参加者名,紫_ロボット名,赤_参加者名,赤_ロボット名,黄_参加者名,黄_ロボット名,緑_参加者名,緑_ロボット名
予選 第1試合,太郎,宇宙号,花子,ロケット号,ひかり,スター号,そら,アーム号
予選 第2試合,参加者E,,参加者F,,参加者G,,参加者H,
```

ロボット名が不要なら、次の5列だけでも登録できます。

```csv
試合名,紫,赤,黄,緑
予選 第1試合,太郎,花子,ひかり,そら
予選 第2試合,参加者E,参加者F,参加者G,参加者H
```

- UTF-8（BOMあり・なし）とShift_JISに対応します。1回200試合、ファイルは1MBまでです。
- 「CSVを選択」→読み込み内容を確認→「この○試合を予定に追加」で登録します。現在の試合や既存の予定を上書きせず、末尾に追加します。
- 試合名・4人の参加者名は必須です。空欄や不正な形式があると行番号を表示し、全体を修正するまで登録しません。各名前は100文字以内です。
- 未開始の予定は編集・削除・「前へ」「後へ」で順番を変更できます。「この試合を準備」で任意の予定を選ぶこともできます。
- 現在準備中の予定の名前は開始前まで編集できます。準備中の試合を別の予定に差し替えると、元の未開始の予定は一覧に戻ります。
- 予定は得点・履歴と一緒に自動保存され、再起動後も引き継ぎます。以前の2026年版の保存データも、そのまま読み込めます。
- 「準備」は名前の設定と得点初期化までです。競技タイマーは「3・2・1で競技開始」を押してから始まります。

## 採点

| 項目 | 点数 | 上限 |
|---|---:|---:|
| スタートゾーンから完全に出る | 20点 | 20点 |
| うちゅうエリアに完全に入る | 20点 | 20点 |
| A デブリ | 1個25点、最大4個 | 100点 |
| B 正しい燃料・不純物の仕分け | 1個30点、最大4個 | 120点 |
| C 落としたサンプル | 1個5点、最大12個 | 60点 |
| D 正しい色の箱への仕分け | 1個20～40点、各箱最大4個 | 480点 |
| **合計** | | **800点** |

Dは青・黄・赤の各箱に入った **正しい色と違う色の個数を、4個を超える分も含めて** 入力します。

```text
Dの単価 = 20 + 5 × Bの正しい仕分け数
箱ごとの得点対象数 = max(0, min(正しい色の個数, 4 - 違う色の個数))
```

例：赤の箱に赤4個・黄1個の場合は、最低点になる4個を選ぶため赤3個分の点数になります。違う色が4個以上なら、その箱は0点です。追加や訂正で点数が下がる場合も、最新の状態で再計算します。

Cには、持っている玉・箱に運んだ玉・リトライで戻した玉も含め、採点対象数を最大12個まで入力します。到達取り消しはうちゅう到達の20点も取り消します。失格者は得点・順位の対象外です。

順位は得点の降順、同点ならうちゅう到達順です。同点では到達者を未到達者より上位とし、未到達者同士は同順位のまま確定できます。タイの次の順位は人数分を飛ばします（1位タイが2人なら次は3位）。

## 試合ごとの結果CSV

主審画面で結果を確定すると「結果CSVをダウンロード」が表示されます。トップ画面の試合履歴にも、各試合ごとに同じボタンがあります。

- 1ファイルに、その試合の4人分をコート順（紫・赤・黄・緑）で出力します。
- 試合名、確定日時（日本時間）、結果版、名前、ロボット名、順位・同順位・失格、合計点と得点内訳、うちゅう到達順・時刻、判定理由を含みます。
- UTF-8 BOM付き・日本語の列名で出力し、Excelなどで開けます。失格者の合計点・順位と、未到達者の到達順・時刻は空欄です。
- 次の試合が進行中でも、履歴から選んだ試合の確定結果を出力します。再確定した場合は更新後の版を出力します。
- 以前に確定した試合も出力できます。既存の確定順位は自動で書き換えません。同順位として確定し直したい場合は、主審画面で確定解除し、必要に応じて「自動判定に戻す」から再確定してください。

## 会場・配信

- `/screen`：4人を2×2で表示する会場画面。ブラウザを全画面にして使用します。音声は明示的に有効にした画面だけで再生します。
- `/streaming-overlay`：**1600×900** の透過背景。OBSのブラウザソースを同サイズに設定します。4人分の表示、共通タイマー、試合名を表示し、音声は出しません。
- 接続断中は最後の表示を残して警告し、入力操作を停止します。再接続時に最新状態を取得します。未確認の操作を自動再送しないため、応答待ち中に切断した場合は個数を確認してから再操作してください。

## 自動保存と復元

- 更新・フェーズ遷移・結果確定時に `save/current.json` に保存し、直前の保存を `save/previous.json` に残します。終了後は `save` フォルダーごとコピーすると記録を保管できます。
- 初回起動時に保存先を自動作成します。再起動時は試合と履歴を復元し、停止している間に競技時間が過ぎた場合は採点確認へ進みます。
- 保存失敗は画面に表示し、試合はメモリ上で続行します。原因解消後、試合管理の「保存を再試行」を押します。警告が消えるまではサーバを終了しないでください。
- 最新ファイルを読み込めない場合はバックアップを復元して警告します。両方を読み込めない場合は、記録の上書きを避けて起動を停止します。

### 別のPCへ記録を引き継ぐ

1. 新しいPCでソフトを取得し、初回セットアップまで済ませます。
2. 元のPCと新しいPCのサーバを両方停止します。
3. 元のPCの `save` フォルダーを、新しいPCのこのREADMEがあるフォルダーへコピーします。保存先を変更している場合は、実際の `D2_SAVE_DIR` の内容をコピーしてください。
4. 新しいPCで起動し、試合名・履歴・予定が復元されたことを確認します。

記録はサーバPCに保存されます。入力用スマホに移す作業は不要です。`save` はGitの管理対象外なので、GitHubへのコミットや `git clone` だけでは大会記録は引き継がれません。

## 更新する場合

サーバを停止し、`save` フォルダーを別の場所にバックアップしてから更新します。Gitで取得した場合は、このREADMEがあるフォルダーで次を実行します。

```powershell
git pull --ff-only
npm.cmd ci
npm.cmd run build
npm.cmd start
```

ZIPで取得した場合は、新しいZIPを別フォルダーに展開してセットアップし、前述の手順で `save` を引き継ぎます。ソースコードを変更した場合も、反映には再ビルドとサーバの再起動が必要です。

## よくある問題

| 状況・エラー | 対処 |
|---|---|
| `node` / `npm.cmd` が見つからない | Node.jsをnpmと一緒にインストールし、ターミナルを開き直します。`node --version` と `npm.cmd --version` を確認してください。 |
| `npm.ps1` を実行できない | Windowsでは `npm` の代わりに `npm.cmd` を使用します。このREADMEのコマンドもその表記です。 |
| `npm ci` が失敗する | インターネット接続を確認し、`package.json` と `package-lock.json` があるフォルダーで実行します。学校・会社の回線に制限がある場合は管理者に確認してください。 |
| `Build files are missing` / `Setup or build files are missing` / `Cannot find module` | `setup.cmd` を実行するか、`npm.cmd ci` → `npm.cmd run build` を実行します。途中のエラーがないことも確認してください。 |
| `EADDRINUSE` / `address already in use` / ポート8000使用中 | サーバがすでに起動していないか、まず `http://localhost:8000` を開きます。起動済みならその画面を使用するか、元の起動ウィンドウでCtrl+Cを押してから再起動します。別のアプリが使っている場合は、ポートを変更します。 |
| サーバのウィンドウが見つからないのにポート使用中 | `netstat -ano \| findstr :8000` で `LISTENING` 行のPIDを調べ、タスクマネージャーで該当プロセスを確認します。終了する前に得点板の「保存を再試行」で記録を保存してください。ほかのアプリのNode.jsプロセスまでまとめて終了しないでください。 |
| PCでは開けるがスマホでは開けない | 同じLANか、URLが `http://PCのIPv4:8000` か、Windowsファイアウォールが許可しているかを確認します。ゲストWi-Fi・端末間通信禁止も確認してください。 |
| 保存に失敗する | 保存フォルダーの書き込み権限・空き容量を確認し、試合管理の「保存を再試行」を押します。警告が消えるまでサーバを終了しないでください。 |
| 会場で音が出ない | `/screen` で「音声を有効にする」を押し、ブラウザとPCの音量を確認します。複数の画面で有効にすると重複再生します。 |
| 更新した画面が出ない | 再ビルド後にサーバを再起動し、ブラウザを再読み込みします。WindowsではCtrl+F5も試してください。 |

## macOS / Linuxでのセットアップ

Node.jsとnpmをインストールし、このREADMEがあるフォルダーで以下を実行します。`.cmd` ファイルはWindows専用です。macOS / Linuxでは次のコマンドを使います（これらのOSでの動作は未確認です）。

```sh
npm ci
npm run build
npm start
```

ポート・保存先を変更する場合の例です。

```sh
PORT=8001 D2_SAVE_DIR="$HOME/D2-2026-records" npm start
```

## 開発・検証

通常の運用にこれらの検証コマンドは不要です。ソースコードを変更したときに使用します。WindowsでPowerShellの実行ポリシーにより止まる場合は、ここでも `npm` を `npm.cmd` に読み替えてください。

```powershell
npm run typecheck
npm run lint
npm test
npm run build
npm run dev
```

`dev` はサーバを8000番、Viteを通常5173番で起動します。`PORT` の指定を解除し、通常起動中のサーバは停止してから実行してください。開発中は `http://localhost:5173` を開きます。クライアント更新とサーバ再起動に対応し、再起動後も自動保存から復元します。

Google Chromeがインストールされている環境では、ビルド後に `npm run test:browser` で登録から確定までのブラウザテストを実行できます。Microsoft Edgeを使う場合は `$env:D2_BROWSER_CHANNEL = 'msedge'` を指定します。テスト用の試合は一時保存先を使い、本番の記録は変更しません。画面キャプチャは `test-results/` に出力します。

- `shared/`：2026年の設定、型、入力検証、採点・順位処理。
- `server/`：WebSocket、サーバ基準のタイマー、保存・復元。
- `client/`：React・Redux・MUIによる操作・表示画面。
- `tests/`：採点、混色、入力境界、順位、到達順訂正、確定・訂正、タイマー、7端末同期、再接続、再起動、保存失敗の自動テスト。

ルールや色の設定を変更したら `shared/config.ts` と関連する入力検証・テストを更新し、再ビルドしてください。採点の基準は冒頭に記載した2026年ルールブックVer.3です。ルールブック本体はこのリポジトリに含まれず、ビルド・実行時にも読み込みません。

## 外部参照インターフェース

- `GET /api/state`：現在の試合、`score`に相当するコート別入力（`match.fields.court1`～`court4`）、順位・得点内訳、履歴、保存警告を返します。
- `GET /api/health`：稼働状態・ルール版・更新番号。
- `/ws`：初回は `welcome`、更新は `state` として全状態を配信します。操作は `shared/model.ts` の `Command` を `{ type: 'command', requestId, command }` で送ります。成功は `ack`、不正・古い試合への操作は `error` を返します。2025年版のRedux action直接送信とは互換性がありません。

ローカル会場の担当者が操作する構成で、認証機能は含めていません。大会方式の変更、トーナメント管理、外部サービス連携は対象外です。
